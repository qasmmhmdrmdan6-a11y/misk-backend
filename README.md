# باك إند متجر مسك — دليل الربط خطوة بخطوة

## 1) إنشاء مشروع Supabase
1. روحي على supabase.com وسجّلي دخول (فيه باقة مجانية كفاية جدًا للبداية).
2. "New Project" → اختاري اسم وباسورد لقاعدة البيانات واحفظيه.
3. لما المشروع يخلص إنشاء (بياخد دقيقة أو اتنين)، روحي على **SQL Editor** من القائمة الجانبية.
4. افتحي ملف `sql/schema.sql` من المشروع ده، انسخي محتواه بالكامل، الصقيه في SQL Editor، واضغطي **Run**.
   - ده هيعمل جداول المنتجات والطلبات وجدول الأدمن، وهيفعّل حماية الصفوف (RLS).

## 2) إنشاء حساب الأدمن (بدل الباسورد الثابت في الكود)
1. من القائمة الجانبية: **Authentication → Users → Add user**.
2. حطي إيميل وباسورد قوي (ده هو اللي هيدخلي بيه لوحة التحكم بدل `misk2026`).
3. Supabase هيشفّر الباسورد ده تلقائيًا (bcrypt) — إحنا معندناش وصول ليه أبدًا حتى في الباك إند.
4. انسخي الـ **User UID** بتاع الحساب ده (هتلاقيه جنب اسم اليوزر في نفس الصفحة).
5. ارجعي على **SQL Editor** وشغّلي السطر ده (بدّلي `USER_UID_HERE` بالـ UID اللي نسختيه):
   ```sql
   insert into admins (user_id) values ('USER_UID_HERE');
   ```
   ده اللي بيحوّل الحساب ده من "مستخدم عادي" لـ "أدمن" معتمد.

## 3) جمع مفاتيح Supabase
من **Project Settings → API** هتلاقي:
- **Project URL** → ده الـ `SUPABASE_URL`
- **anon public key** → هنستخدمه في كود المتجر (الفرونت إند) لتسجيل دخول الأدمن ورفع صور الإيصالات، آمن يظهر للعامة
- **service_role key** → ده سري جدًا، هيتحط في الباك إند بس (متحطيهوش في كود الموقع أبدًا)

## 4) إنشاء مكان تخزين صور الإيصالات (Storage Bucket)
1. من القائمة الجانبية: **Storage → New bucket**.
2. اسم الباكيت: `receipts` بالظبط (المهم يكون نفس الاسم ده لأن الكود بيستخدمه).
3. فعّلي خيار **Public bucket** عشان تقدري تشوفي الصورة في لوحة التحكم من غير تعقيد إضافي.
4. روحي على **Storage → Policies** وضيفي policy جديدة للباكيت ده تسمح بـ **INSERT** لأي حد (public) - عشان العميلة تقدر ترفع الإيصال وهي لسه مش مسجلة دخول كأدمن. مثال أسهل: من نفس الشاشة اختاري "For full customization" وحطي:
   ```sql
   create policy "public can upload receipts"
   on storage.objects for insert
   with check (bucket_id = 'receipts');
   ```

## 5) تشغيل الباك إند
```bash
cd misk-backend
cp .env.example .env
# افتحي .env واملي SUPABASE_URL و SUPABASE_SERVICE_ROLE_KEY
npm install
npm start
```
لو كل حاجة تمام هتشوفي: `✅ الباك إند شغال على بورت 3000`

جربي في المتصفح: `http://localhost:3000/health` → المفروض يرجع `{"status":"ok"}`

## 6) رفع الباك إند لسيرفر حقيقي (Deployment)
أسهل خيارات مجانية/رخيصة: **Render** أو **Railway**.
- اربطي حساب GitHub وارفعي مجلد `misk-backend` كـ repo.
- في Render/Railway: "New Web Service" → اختاري الـ repo → Build command: `npm install` → Start command: `npm start`.
- في إعدادات الـ Environment Variables، ضيفي نفس المتغيرات اللي في `.env` (مترفعيش ملف `.env` نفسه على GitHub).
- هياخد لينك زي: `https://misk-backend.onrender.com`

## 7) ربط الفرونت إند (موقع المتجر) بالباك إند
هغيّر كود الموقع نفسه (`index.html`) عشان يكلم الباك إند ده بدل التخزين المؤقت.
اللي هتحتاجي تعمليه إنتِ بس: تحطي رابط الباك إند الحقيقي (بعد الرفع) بدل `http://localhost:3000` في أول الملف، ومفتاح `SUPABASE_URL` و`anon key` بتوع تسجيل دخول الأدمن.

## ملاحظات أمان مهمة
- **service_role key**: أقوى مفتاح عندك، لو حد وصله يقدر يمسح قاعدة البيانات كلها. متحطيهوش غير في متغيرات بيئة السيرفر.
- **anon key**: آمن يظهر في كود الموقع، لأن صلاحياته محدودة بسياسات RLS اللي عملناها.
- لو عايزة تضيفي أدمن تاني، كرري خطوة (2) بس بإيميل وباسورد جديد.
- لو حسبتِ حساب أدمن غلط أو عايزة تلغي صلاحيته، امسحي الصف بتاعه من جدول `admins` (مش هتمسحي الحساب نفسه من Auth).
